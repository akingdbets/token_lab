# 로컬 test 실행 이력과 복합 의미 손실 비교

분석일: 2026-11-05. 현재 작업 폴더에 보존된 완료 test run 5개를 대상으로 저장된 trials/summary를 읽었다. 신규 모델 호출과 점수 수정은 하지 않았다. 원격 저장소에서 받아온 test_v1.md와 test_v1_default.md의 별도 실행도 문서 보고값으로 추가했다. 원자료 재계산과 문서 인용은 구분한다. 형제 저장소의 20261014 test 포함 40건 실행은 현재 freeze 139문항 전체 실험이 아니므로 아래 주 비교에서 제외했다.

## 1. 같은 생성 설정의 기법 비교

정확도는 유효 채점 문항 평균, 절감률은 전체 입력 토큰 합계, 복합 손실은 문항별 손실 평균이다.

| 실행/조건 | 입력 절감 | 정확도 | 복합 의미 손실 | NOT FOUND | 유효 채점 |
|---|---:|---:|---:|---:|---:|
| A none | 0.00% | 99.28% | 0.00% | 0/139 | 139 |
| A rule | 20.77% | 98.92% | 3.60% | 0/139 | 139 |
| A LL2 r50 | 34.60% | 92.51% | 17.69% | 5/139 | 139 |
| D repair r50 | 33.23% | 95.32% | 11.10% | 2/139 | 139 |
| A LL2 r30 | 50.65% | 75.54% | 29.69% | 24/139 | 139 |
| D repair r30 | 47.87% | 90.71% | 16.72% | 4/139 | 139 |
| A rule→LL2 r50 | 47.24% | 87.11% | 19.96% | 7/139 | 139 |
| E rule→repair r50 | 45.66% | 94.50% | 14.54% | 1/139 | 138 |

E의 c0172는 fact judge가 length 오류를 내 점수가 없다. 누락을 0점으로 처리하지 않는다. E의 정확도는 138문항 기준이며 나머지 지표는 문맥/응답 139건 기준이다.

## 2. 변화와 검정

질문 단위 paired bootstrap 10,000회, seed 42, percentile CI. 완전 정답 여부는 양측 exact McNemar, 3개 기법 비교를 Holm 보정했다. 문서별 군집 의존성을 반영하지 않은 사후 탐색 통계다.

| 비교 | 정확도 변화 [95% CI] | 절감률 변화 | 복합 손실 변화 [95% CI] | 완전정답 Holm p |
|---|---|---|---|---:|
| r50→repair r50 | +2.82 [−0.96, +7.07]%p | −1.38%p | −6.59 [−10.13, −3.51]%p | 0.5811 |
| r30→repair r30 | +15.17 [+8.81, +21.76]%p | −2.78%p | −12.97 [−17.42, −8.85]%p | 0.000577 |
| rule→LL2 → rule→repair | +7.49 [+2.60, +12.68]%p | −1.57%p | −5.42 [−8.73, −2.48]%p | 0.0618 |

마지막 비교의 정확도는 공통 138문항(기존 87.02%, 신규 94.50%)으로 계산했다. 다른 정확도 비교와 모든 의미 손실 비교는 139문항이다.

r30은 평균 점수 차이와 완전 정답률 모두에서 개선이 뚜렷하다. r50은 개선 점추정이 양수지만 불확실하다. hybrid는 평균 부분점수 차이 CI가 양수이나 완전 정답률의 Holm p는 0.05 미만이 아니다. 서로 다른 검정 대상을 혼동하지 않는다.

## 3. 의미 손실 지표 분해

문항별 정의는 `L = max(1 − semantic_sim, 1 − entity_retention)`이다. semantic_sim은 원문/최종 문맥의 임베딩 코사인 유사도, entity_retention은 평가셋 핵심 표현의 정규화 문자열 보존율이다. 16.72%를 실제 의미의 16.72%가 사라졌다는 비율로 해석하지 않는다. 문항별 max를 평균하므로 두 평균 손실의 max와도 다르다.

| 조건 | 문서 임베딩 유사도 | 핵심 표현 보존율 | 복합 손실 |
|---|---:|---:|---:|
| LL2 r50 | 93.14% | 87.77% | 17.69% |
| repair r50 | 93.32% | 94.96% | 11.10% |
| LL2 r30 | 89.08% | 78.06% | 29.69% |
| repair r30 | 90.01% | 92.09% | 16.72% |
| rule→LL2 | 92.54% | 85.97% | 19.96% |
| rule→repair | 92.75% | 91.73% | 14.54% |

개선은 주로 문자열 기준 핵심 표현 보존율에 나타난다. 임베딩 유사도 증가는 r50 약 0.18%p, r30 약 0.93%p, hybrid 약 0.21%p로 작다. 관계·조건의 의미를 전부 회복했다는 증거는 아니다.

참고 진단: A drop_evidence는 입력 절감 1.94%, 임베딩 유사도 98.83%인데도 정확도 37.83%, 복합 손실 54.99%다. 문서 전체 유사도만으로 필요한 작은 근거 손실을 포착하지 못한다. empty는 절감 94.99%, 정확도 0, 복합 손실 100%다. 두 진단 조건은 압축 기법 순위에서 제외한다.

## 4-1. 기존 압축기의 API 기본 설정 실험까지 포함한 비교

앞선 로컬 원자료 표에서 빠졌던 기존 본실험의 재평가다. 출처는 [test_v1_default.md](test_v1_default.md). 기존 압축기 기본 설정 run은 `luna-default-20261103`이며, `20261102-205826`의 압축 문맥을 재사용했다. 해당 두 run의 원시 폴더는 현재 확인한 작업 폴더와 형제 저장소에서 찾지 못해 아래 기존 조건 값은 문서 인용이다.

| 조건 | temperature 요청 | 추론 요청 | 출력 상한 | 입력 절감 | 정확도 | 복합 의미 손실 |
|---|---|---|---:|---:|---:|---:|
| 기존 none, luna 기본 | 생략 | 생략 | 4096 | 0% | 98.1% | 0%† |
| 기존 rule, luna 기본 | 생략 | 생략 | 4096 | 20.8% | 99.3% | 약 3.6%† |
| 기존 LL2 r50, luna 기본 | 생략 | 생략 | 4096 | 34.6% | 91.2% | 약 17.7%† |
| repair r50, luna 기본 (C) | 생략 | 생략 | 4096 | 33.23% | 93.61% (137) | 11.10% |
| 기존 LL2 r30, luna 기본 | 생략 | 생략 | 4096 | 50.6% | 80.2% | 약 29.7%† |
| repair r30, luna 기본 (C) | 생략 | 생략 | 4096 | 47.87% | 90.95% (139) | 16.72% |
| 기존 rule→LL2, luna 기본 | 생략 | 생략 | 4096 | 47.2% | 92.1% | 약 20.0%† |

† 기본 설정에서 의미 손실을 새로 측정한 보고값이 아니다. test_v1_default.md가 원래 문맥 재사용을 명시하므로 [test_v1.md](test_v1.md)의 같은 원본 문맥 지표를 연결한 값이다. 원자료의 문맥 해시를 이번에 대조한 결과는 아니며 보고서 수준의 연결이다. 값은 원본 문서의 반올림 정밀도에 맞췄다.

기존 LL2와 repair의 기본 설정은 기록상 temperature/추론 생략과 출력 상한이 일치한다. 그러나 서로 다른 run·원문 압축 실행에서 얻었고 기존 원자료가 없어 문항 대응 검정/문맥 동일성 검증은 하지 못했다. r50은 약 +2.4%p, r30은 약 +10.7%p의 정확도 차이가 있으나 이 인용 비교에서 유의성을 계산하지 않는다.

새 rule→repair(E)는 temperature 0·추론 none·상한512이므로 위 기본 설정 hybrid와 같은 설정의 수정군으로 놓으면 안 된다. rule→repair의 기본 설정 결과는 아직 없다.

참고로 같은 문서는 기존 압축기의 통제 설정 run `20261102-205826`도 보고한다. 정확도는 none 99.3%, rule 99.1%, r50 91.3%, r30 74.5%, hybrid 88.8%다. 이 역시 로컬 A(`20261103-001108`)와 같은 run이 아니므로 수치를 섞지 않는다. terra 기본 설정 실험은 모델 효과 대조이며 luna 기법의 직접 비교군과 별도로 해석한다.

## 5. 유형별 결과와 trade-off

| 유형 | A r50 | D repair r50 | A r30 | D repair r30 | A hybrid | E rule→repair |
|---|---:|---:|---:|---:|---:|---:|
| fact | 89.47% | 100.00% | 47.37% | 94.74% | 76.32% | 94.74% |
| code | 100.00% | 100.00% | 100.00% | 100.00% | 97.62% | 100.00% |
| procedure | 92.50% | 93.89% | 86.67% | 84.17% | 93.61% | 91.94% |
| multi | 85.63% | 83.91% | 65.52% | 78.74% | 79.31% | 88.69% (28) |

새 standalone repair r50은 현재 수정 조건 중 정확도가 가장 높고, rule→repair는 정확도 94.50%를 유지하면서 절감률이 45.66%다. standalone repair r30은 47.87%로 더 많이 줄이지만 정확도는 90.71%다. 단, hybrid는 1문항 채점이 없고 자동 채점 변동이 있어 확정 순위로 과장하지 않는다.

개선은 유형에 균등하지 않다. 사실형 회복이 크지만 r30의 procedure는 하락했고, hybrid도 procedure가 하락했다. 문장 선정이 절차 전체/하위 질문 근거를 모두 확보하지 못하는 한계가 남아 있다. 단순히 복합 손실 감소만으로 전 유형의 답변 개선을 주장하지 않는다.

모든 수정 조건은 기존 프로젝트의 절감≥50%, 정확도 유지율≥90%, 복합 손실≤5%를 동시에 달성하지 못했다. 의미 손실 5% 이내 조건도 충족하지 못한다. 보존율과 정확도가 개선됐다는 것과 목표 달성은 구분한다.

## 재현

```bash
python3 docs/analysis/compare_test_history.py
```

위 재현 스크립트와 출력 JSON은 로컬에 별도 보존하며, 문서 한 개로 구성한 이번 PR에는 포함하지 않는다. 출력: results/analysis/test_history_20261105/comparison.json. 모든 조건의 수치·유형별 요약·채점 오류·설정·원자료 SHA-256·문맥 동일성 검사를 보존한다. 원시 로그가 별도로 필요하다. 이 분석은 PR 브랜치를 수정하거나 원점수를 고치지 않았다.
