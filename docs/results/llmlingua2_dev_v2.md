## 해석

### 절감률

- 원문 대체가 없어지면서 r30 은 38.3% → **47.5%**, rule>llmlingua2 는 39.8% → **44.7%** 로 올랐다. v1 에서 계산한 "31문항 기준 상한"(r30 47.7%)과 거의 같다
- 문서 1개 문항(31문항)의 압축 결과는 거의 그대로다 (입력 절감 r30 47.7% → 48.1%, 문항별 차이 최대 22 토큰). 맨 앞 경계 줄도 마커로 빼면서 모델 입력이 조금 바뀐 정도다
- **r30 도 입력 토큰 절감 50% 에 못 미친다** (문맥 기준으로는 50.3%). 코드 블록(문맥의 평균 32%)을 통째로 남기는 정책에서는 r30 이 사실상 상한이다

### 정확도 유지율이 내려간 이유

r30 은 90.00% → 87.14%, rule>llmlingua2 는 90.48% → 84.76%. v1 과 정확도가 달라진 문항은 다음뿐이다.

| 압축기 | 내려감 | 올라감 |
|---|---|---|
| r30 | c0015 (1.00 → 0.50, 이번에 처음 압축됨), c0021 (1.00 → 0.00) | c0024 (0.50 → 1.00) |
| rule>llmlingua2 | c0021 (1.00 → 0.00), c0034 (1.00 → 0.00) | - |

- **c0015**: 경계 사례 fact 하나의 판정 흔들림이다 (위 참고). 수정으로 압축되면서 생긴 정보 손실로 보기 어렵다
- **c0021** (정답 `DependencyScopeError`): v1·v2 압축 문맥이 사실상 같다. 두 run 모두 같은 줄이 `dependency rule only DependencyScopeError route.` 로 남았는데,
  v1 은 맞혔고 v2 는 NOT FOUND 다. "request-scoped 가 function-scoped 에 의존하면" 이라는 조건이 지워져, 답변 모델이 이 줄을 근거로 쓸지 말지가 실행마다 갈린 것으로 보인다
- **c0034** (rule>llmlingua2): 식별자 쪼개짐(`OAuth2 PasswordRequestFormStrict`)은 v1 에도 있었다. v1 은 그래도 맞혔고 v2 는 NOT FOUND 다. 같은 손상 위에서 답변이 갈렸다

정리하면 유지율 하락은 대부분 **압축이 이미 핵심 문장을 많이 깎은 fact 문항에서 답변이 실행마다 갈린 것**이다. 수정으로 새로 압축된 multi 4문항 중 정보 손실로 틀린 문항은 없다.
35문항에서 1문항이 1.00 → 0.00 이면 유지율이 2.9%p 움직이므로, 90% 경계 판단은 반복 측정 없이는 어렵다.

### 목표 대비

| 압축기 | 입력 절감 | 유지율 (잠정) | 절감 50% | 유지율 90% |
|---|---|---|---|---|
| llmlingua2_r30 v2 | 47.50% | 87.14% | X | X |
| rule>llmlingua2 v2 | 44.66% | 84.76% | X | X |

**두 목표를 모두 만족한 압축기는 없다.** v1 에서 유지율 90% 경계에 있던 두 압축기는 이번 실행에서 90% 아래로 내려갔다.
의미 손실은 모든 압축 문항이 5% 를 넘는다 (평균 0.155~0.239). 지표·기준 조정은 v1 과 마찬가지로 회의 안건으로 남긴다.

### 가장 취약한 유형: fact

fact 정확도는 r30·rule>llmlingua2 모두 0.636 이다 (11문항 중 4문항이 0). 틀린 4문항 중 셋(c0020, c0031, c0034)은 정답 문자열 자체가 압축 문맥에서 사라지거나 바뀌었다.

- c0020: 따옴표가 지워짐 (`"request"` → `request`)
- c0031·c0034: 질문 식별자(`WebSocket`, `OAuth2`)를 force token 으로 먼저 치환하면서 그 식별자로 시작하는 더 긴 정답 식별자가 공백으로 쪼개짐

code 유형은 코드 블록을 통째로 보존해 1.000 을 유지했다.

## 후속 과제

1. **식별자 쪼개짐 수정**: 질문 식별자가 더 긴 식별자의 앞부분일 때(`OAuth2` / `OAuth2PasswordRequestFormStrict`, `WebSocket` / `WebSocketDisconnect`) 긴 식별자를 먼저 보호한다. fact 오답 2문항(c0031, c0034)의 직접 원인

3. **테스트셋 측정**: dev 는 none 정확도가 1.000 으로 천장이다. 위 두 가지 뒤에 test split 으로 측정한다
