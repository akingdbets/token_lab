# 멀티턴용 압축 (질문을 보지 않는 압축) v1

멀티턴에서는 문서를 한 번 압축해 여러 턴에 재사용한다. 압축하는 시점에 앞으로 나올 질문을 모르므로,
보호 기준을 "질문과 관련 있는가"에서 "답이 될 만한 형태인가"로 바꾼다. rule 은 항상 먼저 적용하고
그 위에 다음 압축을 붙인다 (`rule>X`). 비교 기준선은 rule 단독이다.

## 커밋

| 커밋 | 내용 |
|---|---|
| `27250f2` | 질문을 보지 않는 LLMLingua-2 변형 (`llmlingua2_r{30,50,70}_noq`) |
| `ab827ad` | 질문을 보지 않는 문장 단위 선택 압축기 (`sent_{수준}_r{50,70}`) |

### 1. `llmlingua2_r*_noq` (`src/compressors/llmlingua2.py`)

기존 LLMLingua-2 압축기는 질문을 두 곳에서 쓴다. `use_question=False` 이면 둘 다 끈다.

- 질문 식별자를 force token 으로 넣어 보호하는 부분
- 압축 뒤 질문 식별자가 빠지면 원문으로 되돌리는 부분 (`fallback_missing_question_identifier`)

압축 결과가 질문에 따라 달라지지 않는다 (테스트로 확인). 기록의 `safety_policy_version` 에서
`question-identifiers-v1` 이 빠져 기존 결과와 구분된다. test_v1 에서는 원문 대체가 0건이라
두 번째 부분이 결과에 영향을 주지 않았다.

### 2. `sent_*` (`src/compressors/sentence_select.py`)

토큰이 아니라 단위(문장, 목록 항목)를 통째로 남기거나 지운다. 남은 문장은 원문 글자 그대로라,
test_v1 에서 상태 A 오답의 가장 큰 원인이던 구두점 분해(`0.95.0` → `0 95 0`, 9 trial)와
연결어 삭제(5 trial)가 생기지 않는다.

- **항상 보호:** 코드 블록, 문서 경계 줄(`## Document:`), 머리말, 제목, 표 행, 인용, 글자 없는 줄
- **본문 단위 보호 표지:** 인라인 코드, 숫자, 따옴표 리터럴, 식별자(snake_case/CamelCase),
  값·조건 단어(default, not, must, only 등). 어느 표지를 보호할지는 보호 수준으로 고른다.

| 보호 수준 | 보호하는 표지 |
|---|---|
| strict | 다섯 표지 모두 |
| literal | 인라인 코드, 숫자, 따옴표 |
| loose | 숫자, 따옴표 |
| structure | 없음 (위 "항상 보호" 단위만) |

- **점수와 선택:** 보호되지 않은 단위만 LLMLingua-2 단어 보존 확률 평균으로 점수를 매기고,
  점수 높은 순으로 후보 글자의 `keep_ratio` 만큼 남긴다.
- **건너뛰기:** 짧은 문서(`min_chars`, 기본 1500자)는 원문 그대로 둔다.
- **아직 확인 못 한 것:** 실제 LLMLingua-2 점수 계산은 라이브러리 내부 함수
  (`_PromptCompressor__get_context_prob`, llmlingua 0.2.2)를 부른다. 작업 환경에 모델이 없어
  가짜 점수로만 테스트했다. 첫 실행 때 `--limit 2` 로 먼저 확인한다.

## 측정: 지울 수 있는 몫 (모델 없음, 확정)

dev·test 문항의 근거 문서 49개에 rule 을 적용한 뒤, 글자 수 기준으로 쟀다.

- **rule 뒤 문서 구성:** 본문 문장·목록 51%, 코드 블록 34%, 머리말·제목·표 등 15%
- **본문이 걸리는 보호 표지** (중복 포함): 인라인 코드 75%, 식별자 73%, 값·조건 단어 39%, 숫자 30%.
  어느 표지에도 걸리지 않는 본문은 7% 다.

| 보호 수준 | 지울 수 있는 후보 | rule 대비 추가 절감 상한 (keep 70% / 50%) |
|---|---|---|
| strict | 3.4% | 1.0% / 1.7% |
| literal | 10.9% | 3.3% / 5.4% |
| loose | 32.4% | 9.7% / 16.2% |
| structure | 50.9% | 15.3% / 25.5% |

- 처음 계획한 strict 는 이 위키에서 지울 몫이 거의 없다. 39개 문서 모두 보호 비율 80% 이상이었다.
- 거의 같은 코드 블록(유사도 0.8 이상)은 문서의 0.6% 라, 코드 블록 중복 제거는 효과가 없다.
- 추가 절감은 글자 기준 상한이다. 토큰 절감과 정확도는 실험으로 확인한다.

## 다음 실험 [계획 외]

test 에서 loose 와 structure 를 rule 과 나란히 돌린다. test_v1 계획은 test 를 결론용으로
한 번만 쓰기로 했으므로, 이 실행은 계획 외로 표시한다.

```

EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split test --compressors "none,rule,rule>sent_loose_r70,rule>sent_structure_r70"
```

## 이후 후보

- **기준점(threshold) 선택:** 비율을 고정하면 군더더기 많은 문서는 덜 지우고 빽빽한 문서는 억지로 지운다.
  점수가 기준 미만인 단위만 지우고, 실제 절감량과 정확도를 같이 보고한다.
- **예상 질문 + 문장 관련도 모델:** 문서마다 예상 질문을 미리 만들고, Provence 같은 문장 단위 모델로
  "어느 예상 질문에도 필요 없는 문장"만 지운다. 예상 질문은 평가셋을 보지 않고 만든다.
- **NOT FOUND 재시도:** 답이 NOT FOUND 뿐이면 그 턴만 원문으로 다시 묻는다. 확신 있게 틀린 답은
  못 잡고, 프롬프트 캐시를 깨므로 재시도 비용을 따로 집계한다.
- **멀티턴 평가셋:** 앞 턴 답을 참조하는 질문, 대화 기록이 늘어나는 비용은 지금 단일 턴 평가셋으로 못 잰다.

## 턴마다 질문으로 추출하는 버전 (`qx_*`, `src/compressors/query_extract.py`)

멀티턴에서 압축 결과를 재사용하지 않고, 턴마다 그 턴의 질문으로 원문에서 다시 고른다.
단위와 보호 규칙은 `sent_*` 와 같고, 후보 점수만 질문 관련도다. 추출형이 토큰 가지치기보다
낫다는 비교 연구(Jha et al. 2024, arXiv 2407.08892)가 근거다.

- **점수:** `bm25` (질문 단어로 문서 안 후보를 BM25, 식별자는 통째로 + 조각으로) 또는
  `emb` (질문과 후보의 임베딩 코사인, 후보 임베딩은 캐시해 다음 턴엔 질문 임베딩만 든다)
- **선택:** 후보 글자의 `keep_ratio` 까지 점수 높은 순으로 남긴다. 상한이라 점수 0(질문과 겹치는 데 없음)인
  후보로는 채우지 않는다. 후보 점수가 모두 0 이면 그 문서는 그대로 둔다.
  `min_score` 를 주면 기준점 방식(문서 안 최고점 대비 비율)으로 고른다.
- **이름:** `qx_{bm25|emb}_{loose|structure}_r{30,50}`, 예: `"rule>qx_bm25_loose_r50"`
- **비용:** 턴마다 문맥이 바뀌어 답변 모델의 프롬프트 캐시를 못 쓴다. 멀티턴 절감은 원문+캐시와 비교한다.
- **`llmlingua2_repair_v1` (feature/question-guided-repair-v1) 과의 차이:** 그쪽은 LLMLingua-2 토큰 압축 뒤
  질문 관련 상위 문장을 원문으로 되돌려 넣는다. 이쪽은 토큰 압축 없이 문장을 골라 남긴다.

### BM25 측정 (답변 모델 없음, 글자 기준, 확정)

근거 인용문 보존은 rule 뒤에도 찾을 수 있는 인용문 중 압축 뒤에도 통째로 남은 비율이다.
여러 문장짜리 인용문은 한 문장만 빠져도 잃은 것으로 센다.

| 압축기 | dev 추가 절감 | dev 인용문 보존 | test 추가 절감 | test 인용문 보존 | test 인용문 전부 보존 문항 |
|---|---|---|---|---|---|
| rule>qx_bm25_loose_r50 | 14.6% | 93.3% | 15.8% | 94.0% | 127/139 |
| rule>qx_bm25_loose_r30 | 19.8% | 88.9% | 21.6% | 89.9% | 120/139 |
| rule>qx_bm25_structure_r50 | 24.5% | 93.3% | 25.0% | 89.4% | 121/139 |
| rule>qx_bm25_structure_r30 | 34.1% | 84.4% | 34.7% | 84.4% | 114/139 |

추가 절감은 rule 뒤 문맥 대비, rule 절감은 원문 대비 15~16% 다. 설정은 dev 로 고르고 test 는 확인용으로만 쓴다
(test 측정값은 위 표에 같이 적었지만 고르는 데 쓰지 않는다).
