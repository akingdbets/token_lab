# LLMLingua-2 dev 측정 v3: 압축률-정확도 곡선, 3회 반복

> **정확도는 잠정치.** deepseek-flash 채점은 사람 라벨 검증 전이다 (`judge_check_v3.csv`). 토큰·의미 손실 지표는 채점과 무관하므로 확정값이다.

[v2](llmlingua2_dev_v2.md) 이후 PR #30(식별자 쪼개짐 수정)을 반영하고, none·rule·llmlingua2 r70/r50/r30·rule>llmlingua2 를 한 실험으로 같은 설정에서 **3번** 돌렸다.
목적은 두 가지다. 하나는 압축률-정확도 곡선을 채우는 것이고, 다른 하나는 run 간 변동을 보고 none 대비 차이가 우연인지 검정하는 것이다.

## 실행

- 명령 (3번 순서대로): `EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split dev --compressors "none,rule,llmlingua2_r70,llmlingua2_r50,llmlingua2_r30,rule>llmlingua2" --semantic`
- run `20261031-143214`, `20261031-162640`, `20261031-172011` (각 35문항 × 압축기 6 = 210 trial). 모두 git `96d862c`, 중단 없이 종료 (`--resume` 불필요)
- 1회차 도중 한 번 네트워크가 끊겼다 (api.openai.com DNS 실패). 기본 재시도 2번이 실패한 뒤 더 길게 기다리는 네트워크 재시도 2번 만에 이어졌고, 기록 손실은 없다. 2·3회차는 재시도 없음
- 집계: `python src/repeat_stats.py <run1> <run2> <run3>`. `results/` 는 커밋하지 않음

## 검정: none 대비 (양측, 35문항)

- Wilcoxon 부호 순위 검정 (정확 분포): 문항별 정확도를 3 run 평균한 뒤 (압축 − none) 차이로 검정한다. 0 인 문항은 뺀다
- McNemar 정확 검정: (문항, run) 짝 105개에서 완전 정답(정확도 1) 여부를 본다. b 는 none 만 정답, c 는 압축만 정답인 짝이다. 같은 문항의 run 끼리는 독립이 아니어서 run 별 값도 함께 적었다

| 압축기 | 평균 차이 | Wilcoxon (차이 ≠ 0 문항 수, W+/W−) | p | McNemar 합침 b / c | p | run 별 McNemar p | none 보다 나빠진 문항 |
|---|---|---|---|---|---|---|---|
| rule | 0.000 | 3, 3 / 3 | 1.00 | 2 / 3 | 1.00 | 1.0, -, 1.0 | c0015 |
| llmlingua2_r70 | −0.006 | 4, 4 / 6 | 0.88 | 3 / 2 | 1.00 | 1.0, 1.0, 1.0 | c0024, c0146 |
| llmlingua2_r50 | −0.033 | 5, 3 / 12 | 0.25 | 5 / 2 | 0.45 | 1.0, 0.25, 1.0 | c0015, c0020, c0024 |
| llmlingua2_r30 | −0.046 | 8, 7.5 / 28.5 | 0.16 | 8 / 4 | 0.39 | 1.0, 0.5, 1.0 | c0004, c0020, c0024, c0031, c0146 |
| rule>llmlingua2 | −0.034 | 5, 1 / 14 | 0.13 | 6 / 2 | 0.29 | 0.63, 1.0, 1.0 | c0020, c0021, c0024, c0146 |

**어느 압축기도 none 과 유의한 차이가 없다 (모두 p > 0.1).** 압축률이 높을수록 평균 차이와 W− 쪽 쏠림은 커진다. 다만 dev 35문항에서는 차이가 0 이 아닌 문항이 3~8개뿐이라 검정력이 낮다. "차이가 없다"가 아니라 "이 크기로는 구분할 수 없다"로 읽어야 한다. 5% 수준에서 유의하려면 Wilcoxon 기준 최소 6문항이 모두 같은 방향이어야 한다 (n = 6 이면 최소 p = 0.031).

c0020 은 r50·r30 에서 세 run 모두 0점이다. 그 밖의 대부분은 run 마다 오가는 문항이다.

## run 간 변동

temperature 0, seed 42 여도 gpt-6-luna 의 답변은 결정적이지 않다.

- 같은 (문항, 압축기) 210쌍 가운데 86쌍(41%)은 세 run 의 답변 문자열이 하나 이상 다르다
- 정확도가 run 마다 다른 쌍은 20개다. 20개 모두 답변 자체가 달랐고, 같은 답변에 채점만 다르게 나온 경우는 없다
- none 자체도 c0003, c0006, c0015, c0024 가 run 마다 0.5~1.0 사이를 오간다 (none 정확도 0.986 ± 0.014)
- 큰 뒤집힘의 예: r30 c0031 (`NOT FOUND` → `WebSocketDisconnect`), r30 c0004 (`first` → `last`), rule>llmlingua2 c0020·c0021 (정답 ↔ `NOT FOUND`)

그래서 한 번 잰 값으로 비교하면 압축기 사이 차이를 과대·과소평가할 수 있다. v2 에서 r30 0.871, rule>llmlingua2 0.848 로 잰 값이 이번에는 0.940 ± 0.034, 0.952 ± 0.031 이다. 차이에는 PR #30 수정과 이 변동이 섞여 있다.

run 에 기록된 값은 이전 방식(단어 연속 일치)이다. PR #34 의 정규화 매칭(normalized-v1)으로 소급 계산하면 아래와 같다 (`src/memory_suspect.py`, run 1 / 2 / 3).

- 정규화로 풀린 것은 r30 c0026 (문맥 `asgi_lifespan`, 정답 `asgi-lifespan`) 하나다

- 남은 c0004 (`The last one added`) 와 c0030 (`The override's own signature`) 는 압축 문맥에서 표현이 바뀐 경우다. 기억으로 답한 것인지 사람이 분류해야 한다
