# feat: 질문 기반 섹션 선택 압축기와 파이프라인 조합 지원

질문과 관련 있어 보이는 섹션을 선택하고 내부를 원문 그대로 보존하는 `section_bm25`를 추가한다. 기존 `rule`·LLMLingua-2와 같은 `--compressors` 조건으로 단독 비교하거나 `>`로 앞뒤에 연결할 수 있다.

## 도입 배경과 연구 활용

중심 질문은 **“문서를 압축해도 왜 답을 계속 맞히는가?”**다. rule은 형식·중복을 정리하고, 현재 LLMLingua-2 설정은 코드를 보호하며 주로 설명의 토큰을 줄인다. 섹션 전체를 선택·제외하는 방식을 추가해, 보존 단위가 달라졌을 때 절감률·답변 품질과 남은 설명·코드의 차이를 비교할 수 있게 한다.

새 기법은 단순한 분석 도구가 아니라 실험에 투입할 압축기다. 선택·삭제 기록을 추가로 활용해, 정답이 유지된 입력에 어떤 정보가 남았고 필요한 섹션까지 제외했을 때 답변이 어떻게 바뀌는지 조사한다. 기존 기법보다 우수하다는 전제를 두지 않는다.

## 구현

- 같은 문서·제목 경로의 본문을 섹션으로 묶고, BM25 점수 순위를 한 번 고정한다. 낮은 순위 섹션부터 전체를 제외하며 출력은 원문 순서를 유지한다.
- 설명·코드·목록·표의 내부를 자르거나 재작성하지 않는다. 선택한 내용의 출처·상위 제목을 포함한다. 정답·key_facts·evidence는 선택에 사용하지 않는다.
- `--section-retain-ratio`(기본 0.5), `--section-input-budget`을 추가한다. 예산은 **해당 단계에 들어온 전체 메시지** 기준이다. 절대 토큰 목표가 비율보다 우선한다.
- 최상위 섹션은 통째로 남겨 목표 초과가 가능하다. 초과 여부·선택 ID·점수·원문 위치·삭제 순서·fallback을 trial의 단계별 info에 기록한다.
- 기존 Chain의 순차 전달·비용 합산·단계별 기록을 사용한다. `rule>section_bm25`, `section_bm25>rule`, `section_bm25>llmlingua2`, 역순 및 3단계 조합을 지원한다. resume은 원래 section 옵션을 복원한다.
- 답변 프롬프트 로더를 공용 모듈로 이동해 실험과 압축 예산 계산이 같은 메시지 형식을 사용하게 한다. 프롬프트 v1 내용과 해시 `d12495bd1412`는 유지한다.

```bash
EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split dev \
  --compressors 'none,rule,llmlingua2_r50,section_bm25,rule>section_bm25,section_bm25>llmlingua2' \
  --section-retain-ratio 0.5
```

위 실행 명령은 실제 답변·채점 API를 호출한다. 조합에서 비율은 원문이 아닌 이전 단계 출력 기준이며, 순서에 따라 선택·최종 토큰이 달라질 수 있다. **조합 실행을 지원한다는 것과 조합의 성능 이득이 확인됐다는 것은 구분한다.**

## 완료한 실험으로 보여주는 것

등록 전 진단 구현으로 생성한 단독 압축 결과를 등록 압축기로 정확히 재현했다. 아래 자동 점수는 기존 실험의 답변·판정을 사용하며 이번 PR에서 다시 생성한 답변 점수가 아니다.

| dev 35문항, 각 3회 | 실제 입력 절감률 | 평균 key_facts 점수 |
|---|---:|---:|
| 전체 입력 80% 보존 목표 | 22.45% | 98.25% |
| 전체 입력 50% 보존 목표 | 58.04% | 90.48% |

문항별 평균은 29개 동일·5개 하락·1개 상승이었다. 이어서 유형별 3문항의 미평가 중간 삭제 단계를 각 3회 평가했다. 추가 답변 201개와 기존 끝점 72개를 연결한 91개 상태·273개 관측이다.

- c0029는 815토큰까지 만점이었고, DB fixture 예제를 지운 443토큰에서 3회 모두 NOT FOUND였다.
- c0039는 JWT 예제 코드를 지우기 직전까지 만점이었고, 삭제 후 JWT 로그인 실패 응답을 답하지 못했다.
- c0015의 username 사실은 설명을 지워도 코드가 남을 때 3회 모두 충족됐고, 코드 섹션 제거 후에는 모두 불충족이었다. 이는 남은 코드가 정답 유지에 기여했을 가능성을 뒷받침한다.

## 해석의 한계

- 필요한 블록도 잘못 제외할 수 있다. BM25 순위는 정답 근거의 보증이 아니다. 예산은 최상위 섹션 보존 때문에 엄격한 상한이 아니다.
- dev 탐색 결과이며 12문항은 기존 결과를 보고 골랐다. 끝점과 중간 단계의 호출 시점이 다르고, 같은 문서를 공유하는 문항도 있다.
- c0015 총점은 함수명 명시 기준의 판정 차이로 흔들렸다. 자동 처리 오류 0건이 의미상 채점 정확성을 보장하지 않는다. 원래 점수는 바꾸지 않았다.
- 단독 압축의 현상을 보여주는 결과다. **기법 간 우위, 조합의 정확도·절감 이득, test 일반화, 사전지식 배제, 특정 근거의 단독 인과 효과는 미검증**이다.
- 기존 고정 test 계획·평가셋·채점 프롬프트는 수정하지 않는다. 모델 호출을 포함한 원자료 로그는 별도 보관하며, PR에는 점수·주요 원시 답변·fact 판정·해시를 담은 공유 근거 기록을 포함한다.
