# 질문 기반 섹션 선택 압축기

**`section_bm25`는 질문에 관련 있어 보이는 섹션을 선택하고, 선택한 섹션 내부는 원문 그대로 보존하는 압축 기법이다.** 기존 `--compressors`에 단독·조합 조건으로 지정한다.

## 도입 이유와 연구 질문

연구 질문은 **“문서를 압축해도 왜 답을 계속 맞히는가?”**다. rule은 형식·중복을 정리하고, 현재 LLMLingua-2 설정은 코드를 보호하면서 주로 설명 내부의 토큰을 줄인다. 이들과 다른 정보 보존 방식을 비교하기 위해 섹션 전체를 선택·제외하는 압축기를 추가한다.

이 기법을 같은 실험의 비교 조건으로 사용하고, 선택 기록을 통해 어떤 설명·코드가 남았을 때 답이 유지되는지 조사한다. 필요한 코드도 선택에서 빠질 수 있으므로 의미 보존이나 기존 기법 대비 우위를 보장하지 않는다. 기존 문장·코드 단위 `block_bm25_v2`와는 별도 방식이다.

## 선택 과정

1. 같은 문서·제목 경로의 본문을 한 섹션으로 묶는다. 하위 제목은 별도 섹션이며, 설명·코드·목록·표 내부를 자르지 않는다. YAML 메타데이터는 후보에서 제외한다.
2. 질문과 섹션 본문의 BM25 점수를 한 번 계산한다. 식별자의 구성 단어도 점수 계산에 활용하지만 출력 이름을 바꾸지 않는다.
3. 점수 내림차순으로 고정하고, 낮은 순위 섹션부터 제외한다. 동점은 원문 순서다. 같은 입력의 예산을 낮추면 같은 순위 목록의 뒤쪽을 더 제거한다.
4. 선택한 원문과 해당 출처·상위 제목을 원문 순서로 조립한다. 정답·key_facts·평가용 evidence는 선택에 사용하지 않는다.

## 예산과 조합

`--section-retain-ratio`는 **이 단계에 들어온 전체 메시지**의 보존 목표 비율이며 기본 0.5다. system·질문·메시지 형식을 포함한다. `--section-input-budget`을 주면 토큰 수 목표가 비율보다 우선한다.

최상위 섹션 하나는 온전히 남긴다. 따라서 예산은 엄격한 보장이 아니며, 큰 코드 섹션 또는 고정 지시문 때문에 초과할 수 있다. `best_section_exceeds_budget`, `budget_exceeded`, `fixed_input_exceeds_budget`를 기록한다. 파싱 오류는 원문으로 복구하고 `fallback_error`, `trace.used_original`을 남긴다. 질문과 단어가 겹치지 않으면 원문 순서로 선택하며 `query_overlap=False`로 표시한다.

```bash
# 같은 평가에서 단독 압축기들을 비교 — 실제 답변/채점 호출
EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split dev \
  --compressors 'none,rule,llmlingua2_r50,section_bm25' --section-retain-ratio 0.5

# 앞/뒤 또는 여러 단계의 조합 — 실제 답변/채점 호출
EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split dev \
  --compressors 'none,rule>section_bm25,section_bm25>llmlingua2,llmlingua2>section_bm25,rule>section_bm25>llmlingua2'

# 절대 토큰 목표와 재개
EVAL_DIR=data/evalsets/claude-v1 python src/experiment.py --split dev \
  --compressors 'none,section_bm25' --section-input-budget 1200
python src/experiment.py --resume RUN_ID
```

조합에서는 각 단계의 현재 입력에 비율을 적용한다. `rule>section_bm25`의 0.5는 원문이 아니라 rule 출력 전체 메시지의 절반 목표다. 절대 예산은 section 단계의 목표이며 이후 압축기의 출력에 대한 보장은 아니다. 순서가 바뀌면 선택과 최종 토큰 수가 달라질 수 있다. 재개 시 원래 section 옵션을 복원하며, 예전 run에는 기본값을 적용한다.

조합의 순차 전달·설정·trace·재개는 모의 모델 테스트로 검증했다. **조합의 정확도·절감 이득은 아직 측정하지 않았다.** rule의 중복 코드 대체 뒤 원본 코드가 제외되는 문제, 후단 LLMLingua가 선택한 설명을 다시 줄이는 문제도 실험에서 확인할 대상이다.

## 기록과 검증

`trials.jsonl`의 `info`에 섹션 순위·선택 ID·원문 위치·삭제 순서·실제 토큰을 기록한다. 조합은 기존처럼 단계별 `info`에 남는다. 추가 모델 가중치나 패키지는 없다. 토크나이저는 준비돼 있어야 한다.

```bash
TOKENIZER=tiktoken:o200k_base python -m unittest discover -s tests
TOKENIZER=tiktoken:o200k_base python scripts/replay_section_evidence.py
```

두 번째 명령은 기존 dev 입력 137개를 재생성해 토큰·선택 목록·내용 해시를 검증하며 답변·채점 API를 호출하지 않는다. 답변 재생성이나 독립적인 성능 검증을 뜻하지 않는다.
