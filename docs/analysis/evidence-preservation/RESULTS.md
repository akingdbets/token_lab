# 결과와 연구 한계

## 배경과 손실 분석

강한 토큰 삭제는 정답 값뿐 아니라 주체·동작·조건의 연결과 순서를 손상시킬 수 있다. 기존 Terra test run `20261104-165320`에서 동일 qid의 none과 각 압축 조건을 짝지어 `compressed answer_accuracy < none answer_accuracy`를 추출했다. r30 29건 + r50 12건 = **41개 실패 시행**이며 동일 qid의 다른 조건은 별개 시행이다. 전체 비교 분모는278개, 별도 성공 비교 표본은 유형×조건별2건씩16개다. 문항/파일 조인 누락은0건이었다.

A=정보 삭제, B=관계·조건 손상, C=근거 충분하나 답변 실패, D=Judge/gold 문제로 검토한다. 자동 후보와 사람 라벨을 분리하고 기본 사람 판정은 빈 상태다. 실패 조건부 표본의 원인 비중을 전체 실패 원인 발생률로 일반화하지 않는다. 자동 후보의 근거 exact-match 실패는 삭제의 증명이 아니다.

## 구현과 동일 예산

새 이름은 `qp_identifiers_r30`, `qp_sentences_r30`, `qp_combined_r30`이다. 기존 r30/r50 구현은 수정하지 않았다. 압축 결정 함수에는 질문·원문·고정 system·숫자 예산·토큰 카운터만 전달하며 정답/key_facts/evidence/qid/과거 답변/실패 목록은 받지 않는다. 공개 인터페이스의 diagnostic label도 제거하며 poisoned-label 경계 테스트로 확인한다.

BM25(k1=1.2,b=.75)로 원문 문장·코드 구간을 순위화한다. Combined는 조건·부정·비교·범위·순서 휴리스틱을 가진 관련 구간에1.25배 가중한다. 가용 context 예산35%, 최대18구간 안에서 문서 경계, 관련 문장, 버전/수치/API 식별자를 선택한다. Combined는 보호 예산85%까지 문장을 먼저 넣고 나머지에 식별자를 담는다. 모든 식별자나 문법 관계를 전역 보장하는 알고리즘은 아니다.

선택 원문은 마커로 분리하고 잔여 부분에 로컬 LLMLingua-2를 적용한 뒤 원문 그대로 복원한다. 초과하면 보호되지 않은 단어를 줄이고, 남는 예산에는 원문 단위와 단어 경계 prefix를 추가한다. 합성 filler는 사용하지 않는다. 보호되지 않은 부분은 문장 조각이 될 수 있다.

각 문항의 **새 r30 전체 메시지(system+context+question) 토큰 수**를 공통 목표로 삼는다. 세 변형 모두 dev35/독립31문항에서 추정 예산 초과0건, r30 대비0 또는−1토큰이었다. 실제 API prompt_tokens도 전 문항에서 절대 차이1토큰 이내였다. None/r50은 예산이 다른 참조 조건이다. 기본 r30은 전체 코드 블록을 보호하므로 nominal30%와 실제 전체 입력 보존률은 다르다.

## 실험 절차

- 답변 GPT-6.1 Terra, temperature0, seed42, reasoning_effort=none, answer_v1/512토큰.
- Judge DeepSeek-flash, fact_judge_v2 per_fact/4096토큰. 정확도는 문항별 핵심 사실 충족률을 문항에 동일 가중치로 평균한다.
- dev35문항×6조건=210시행을 새로 평가했다. 기존 답변을 재사용하지 않았다.
- 하나의 사전 정책을 평가하고 코드·설정을 고정했다. 성능에 따른 파라미터 탐색은 하지 않았다.
- 고정 후 Python3.14 공식 문서8개에서 유형별 후보32개를 생성했다. schema/원문 추출본 exact quote/자동 grounding audit를 통과한31개(문서8개)를 확정했다. 거절1개를 교체·재생성하지 않았다.
- 기존 dev/test와 문서 ID 및12단어 shingle 중복은0이다. 기존 test139는 최종 독립 평가에 사용하지 않았다. 독립셋에서 규칙 변경/튜닝 없이186시행을 실행했다.
- API 잔액 부족으로 중단된 dev는 완료 시행과 답변 캐시를 재사용해 이어 실행했다. 독립 평가의 연결 오류1건도 해당 시행만 재개했다. 실패는 원시 이력에 보존했다.

### 실제 답변 변화와 악화

점수 개선10/악화1/동률20. `graphlib` union, `bisect.__lt__`, `heapq.nlargest`의 sorted 식, `copy`의 unchanged/sequence[:] 및 contextlib 관계에서 NOT FOUND→구체 답변 변화가 관찰됐다.

- `ind_copy_3`: deepcopy(component,memo)는 복원됐지만 memo를 opaque하게 다룬다는 사실은 빠져 **0→0.5**의 부분 개선에 그쳤다.
- `ind_copy_4`: Combined가 필드 교체 동작과 named tuple 지원을 누락해 **1→0**으로 악화했다. 복합 key_fact의 all-or-nothing 채점 영향도 있다.
- `ind_graphlib_3`, `ind_functools_3`: r30도 의미상 유효한 절차/annotated registration을 설명한다. optional initial graph와 type inference를 명시해야 하는지에 따라 일부 점수 차이가 달라질 수 있다. 사후에 유리하게 재채점/제외하지 않았다.

## 한계와 비용

1. 새 문서에 대한 독립성은 기존 dev/test와의 독립이지 모델 사전학습과의 독립이 아니다. 문서8개/문항31개의 작은 합성 평가셋이다.
2. 생성 모델과 답변 모델이 같고 gold/검수/채점이 자동이다. 독립 사람 검증 및 외부 모델 재현 전이다. Judge 점수 상승만으로 회복을 확정하지 않는다.
3. 추출본에 UTF-8을 Latin-1로 해석한 것으로 보이는 비ASCII 문장부호 깨짐이 있다. frozen 수집기는 requests.response.text의 기본 해석을 썼다. 모든 조건이 같은 고정 추출본을 사용했고 quote exact-match는 **그 추출본 기준**이다. 평가 후 원문을 수정하지 않았다. 정상 typography의 새 holdout 재현이 필요하며 세부 진단은 `data/preprocessing_diagnostic.json`에 있다.
4. 압축은 로컬 CPU만 사용하므로 추가 LLM API 호출·토큰은0이다. 배포 시 r30 예산 산출 비용도 포함해야 한다. 독립셋 Combined의 잔여 압축/수선 평균은 약1.08초, anchor 산출 포함 약1.66초였지만 모델 최초 로딩/공유 캐시 영향을 받아 엄밀한 latency benchmark는 아니다.
5. 데이터셋 생성8회/자동 감사32회와 평가 토큰은 `data/costs.json`에 기록했다. 중단된 per-fact batch/연결 오류의 미반환 usage가 있을 수 있어 알려진 사용량의 하한이다. 계약 단가를 고정하지 않아 달러 비용을 추정하지 않는다.
6. 이 관찰은 해당 고정 예산·문서 QA 프로토콜에 한정된다. 전체 test 실패 원인 발생률, 일반 기술 QA 우위, 배포 가능한 RAG 성능으로 일반화하지 않는다.
