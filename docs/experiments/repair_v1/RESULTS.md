# 질문 관련 문장 복원: 원리와 실험 비교

이 문서는 새 기법을 적용한 test 사후 실험 두 번을 설명한다. 정확도는 DeepSeek Flash 자동 핵심 사실 채점의 잠정치다. 원점수는 사람 검수로 수정하지 않았다. PR에는 소스·테스트·설명 문서만 포함한다. 원시 실험 로그와 생성된 분석 JSON은 로컬에 별도 보존한다.

## 1. 문제와 설계 가설

기존 LLMLingua-2의 저장 문맥에서 버전 표기의 분해, 기능과 버전 사이의 연결 표현 삭제, 환경변수 설정 주체/조건 삭제, 작업 실행 순서 표현 삭제를 확인했다. 모든 실패의 원인을 전수 분류하거나 삭제가 실패의 단독 원인임을 입증한 것은 아니다.

가설: 전체 문서를 강하게 압축하되 질문 관련성이 높은 문장의 보존이 부족할 때만 복원하면, 추가 입력량을 제한하면서 답변 정확도를 회복할 수 있다. 복원은 문장 내부의 표기·조건·관계를 함께 되돌린다. 관계를 직접 분석하거나 생성 모델로 재작성하지 않는다.

## 2. 실제 구현

```text
질문·원문 → 단어 빈도 코사인으로 상위 3문장 선정
원문 → 기존 LLMLingua-2로 전체 문서 압축
선정 문장 ↔ 정렬로 찾은 대응 압축 구간의 임베딩 코사인
유사도 < 0.85 → 원문 문장 전체 복원 (누적 추가 최대 256토큰)
최종 문맥 → 답변 한 번 생성 → 핵심 사실 채점
```

- 선정은 의미 임베딩 검색이 아니라 단어 일치 기반이다. 관련성 0인 문장은 제외한다.
- 보존 검사는 bge-m3 임베딩을 사용한다. 유사도는 의미 보존을 보증하지 않는다.
- 원문/압축문 대응은 SequenceMatcher 기반 휴리스틱이다. 정렬률 90% 미만이면 복원을 건너뛴다. 반복 표현은 높은 정렬률에서도 오대응될 수 있다.
- 코드는 문장마다 다른 시도를 반복하지 않고 관련성 순서로 한 번 검사/복원한다.
- 복원 문장을 새 마커로 등록하지 않으므로 surface_v1의 추가 마커 한도 문제는 없다. 기반 LLMLingua의 기존 보호 규칙은 유지한다.
- 답변·key_facts·정답 근거 인용문은 복원 판단에 입력하지 않는다.
- 기본 3/0.85/256은 초기 실험값으로 최적이라고 검증되지 않았다.

## 3. 세 실행의 설정

| 실행 | 원래 LL2 | repair, 생각 끔 | repair, 기본 추론 |
|---|---|---|---|
| run | 20261103-001108 | 20261104-211703 | repair-luna-default-20261105 |
| 답변 모델 | gpt-6-luna | gpt-6-luna | gpt-6-luna |
| temperature 요청 | 0 | 생략 | 생략 |
| reasoning_effort 요청 | none | none | 생략 |
| 출력 상한 | 512 | 512 | 4096 |
| 문맥 | LL2 압축 | 새로 압축 후 repair | 바로 앞 repair 문맥 재사용 |
| 분석 대상 | LL2 r50/r30 각 139 | 각 139 | 각 139 |

기본 추론 재평가의 문맥 파일 278개는 생각 끔 repair 실행과 바이트 단위로 동일하다. 두 repair 실행 사이에서 복원 결과 자체가 바뀐 것은 아니다. 답변 모델 프롬프트와 채점 프롬프트의 해시는 동일하다. judge는 deepseek-flash, per_fact다.

논문 test_v1_default.md의 기존 LL2 수치는 별도 run(20261102-205826에서 문맥 재사용)의 결과이므로 아래 로컬 LL2 기준선과 혼합하지 않는다. 그 문서의 기존 기본 설정에 이번 repair 행을 단순 추가해 기법 효과를 계산하면 설정/실행 차이가 섞인다.

## 4. 기존 LL2 대비 repair

| 조건 | 기존 정확도 | repair 생각 끔 정확도 | 변화 | 기존 입력 절감 | repair 입력 절감 |
|---|---:|---:|---:|---:|---:|
| r50 | 92.51% | 94.54% | +2.04%p | 34.60% | 33.23% |
| r30 | 75.54% | 89.99% | +14.45%p | 50.65% | 47.87% |

| 조건 | 정확도 차이 95% CI | 개선/악화 문항 | 완전정답 증가 방향/감소 방향 | Holm 보정 McNemar p |
|---|---|---|---|---:|
| r50 | [-1.56, +6.06]%p | 8 / 6 | 7 / 5 | 0.7744 |
| r30 | [+7.61, +21.28]%p | 27 / 9 | 25 / 7 | 0.004205 |

문항 paired bootstrap 10,000회, seed 42, percentile 95% CI. McNemar는 완전 정답 여부의 양측 정확 검정이며 두 조건을 Holm 보정했다. 문서별 군집 의존성을 반영하지 않는다. r30의 실행 간 개선은 뚜렷하지만 temperature 차이로 기법의 순수 효과라고 확정하지 않는다. r50 개선은 통계적으로 불확실하다.

복원으로 입력이 r50 총 4,621토큰, r30 총 9,327토큰 늘었다. 고정 최종 토큰 예산 비교가 아니며 정확도 회복과 절감률 감소를 함께 보고한다.

## 5. 같은 repair 문맥, 기본 추론 설정으로 재평가

| 항목 | r50 생각 끔→기본 | r30 생각 끔→기본 |
|---|---|---|
| 전체 표시 정확도 | 94.54% (139) → 93.61% (137) | 89.99% (139) → 90.95% (139) |
| multi 공통 유효 표본 | 79.01% → 79.01% (27) | 75.29% → 72.41% (29) |
| procedure | 93.61% → 96.39% | 84.17% → 91.39% |
| 전체 NOT FOUND | 3 → 5 | 4 → 8 |
| multi NOT FOUND | 3 → 4 | 2 → 6 |
| 평균 출력 토큰 | 40.7 → 78.9 | 39.1 → 89.0 |

r50 기본 실행은 c0154/c0155의 fact judge 출력이 length로 잘려 점수가 없다. 0점으로 처리하지 않는다. 전체 표시 평균은 표본이 달라 직접 대응 비교가 아니며, 공통 유효 문항의 정확한 평균과 CI는 analysis.json의 repair_settings에 있다. 답변은 278건 모두 stop으로 종료됐다.

multi의 c0016, c0169, c0170은 한 부분을 답해 0.5점을 받던 응답이 NOT FOUND로 바뀌었다. r30 c0162도 같은 패턴이다. 이는 "답이 없으면 NOT FOUND" 지시 아래 부분 근거가 있는 경우 전체 답변을 포기하는 행동과 부합한다. 내부 판단 과정은 기록하지 않았으므로 원인을 확정하지 않는다. 생각 기능과 출력 상한이 함께 바뀌었고 단일 반복 비교다. 추론 활성화만의 효과로 분리하지 않는다.

## 6. 성공과 실패의 범위

- r30 c0007, c0078, c0168은 기존 NOT FOUND에서 완전 정답으로 바뀌었다.
- c0162는 telemetry 설정은 회복했지만 작업 순서의 근거를 복원하지 못했다.
- c0072는 업그레이드 절차 대신 ASGI·버전 일반 설명을 복원했다.
- 링크만 있는 줄이나 목록 도입문이 상위 후보에 들어가며, 단일 문장 복원으로 목록 전체의 절차를 확보하지 못한다.
- r30은 137/139문항에서 총 394문장, r50은 125/139문항에서 총 257문장을 복원했다. 이 정도로 자주 복원하므로 임베딩 검사가 선택적으로 손실을 구별한다고 주장하기 어렵다.
- c0172는 동일 응답에 이전 1점/이번 0.5점이 부여됐다. c0149 등에도 채점 기준 불일치 후보가 있다. 상세는 judge_review_candidates_20261104.md를 참고한다. 자동 점수를 임의 수정하지 않았다.

## 7. 논문에서 가능한 주장

"기존 압축의 선택 사례에서 기술 표기와 조건·순서 표현의 삭제를 확인하고, 질문 관련 문장을 검사·복원하는 사후 보정 방법을 설계했다. 로컬 test r30 비교에서 입력 절감률 2.78%p 감소와 함께 평균 핵심 사실 정확도 14.45%p 증가가 관찰됐다. 다만 답변 temperature 차이와 자동 채점의 한계로 복원 기법만의 인과 효과를 확정하지 않는다. 같은 복원 문맥에 기본 추론을 적용하면 절차형은 향상됐지만 종합형에서 부분 답변이 전체 거절로 전환되는 현상이 관찰됐다."

피해야 할 주장: 일반화 성능 입증, 관계 손실 직접 탐지, 모든 손실 회복, 임베딩 검사의 독립적 기여 입증, 동일 비용에서의 우위. 동일 생성 설정의 기존/repair 비교와 "검사 없이 상위 문장을 복원"하는 대조가 아직 없다. test를 본 뒤 설계한 사후 개선 실험이다. 원격 임베딩 비용과 CPU 비용도 답변 토큰 절감에 자동 합산되지 않는다.

## 8. 재현과 증거

```bash
python3 docs/experiments/repair_v1/analyze.py > /tmp/repair-analysis.json
python3 -m unittest discover -s tests -p test_sentence_repair.py
```

analyze.py는 로컬 results/runs 아래의 세 실행을 읽고 API를 호출하지 않는다. 다른 위치는 --runs-root로 지정한다. 원자료가 없는 체크아웃에서는 파일 부재 오류를 출력한다. 위 명령으로 통계를 재현하려면 세 run의 trials.jsonl을 별도 전달받아야 한다. 원시 로그·contexts·생성 분석 파일은 PR에 포함하지 않는다. 기존/repair 조건은 registry에서 별도로 선택하며 기존 압축기의 기본 동작은 변경하지 않는다.
