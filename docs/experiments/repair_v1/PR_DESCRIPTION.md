## 문제와 변경

LLMLingua-2가 기술 문서의 단어를 선택하는 과정에서 질문에 필요한 조건·관계·표기 구절이 삭제될 수 있다. `llmlingua2_repair_v1_r30/r50/r70`은 질문 관련 상위 문장과 대응 압축 구간의 임베딩 유사도를 검사하고, 낮은 유사도의 문장을 원문으로 복원한다. 초기 기본값은 top_k=3, threshold=0.85, 추가 입력 상한 256토큰이다. 답변 생성은 최종 문맥으로 한 번 수행한다.

기존 압축기의 기본 동작은 유지한다. 원문 대응은 휴리스틱이며 정렬 불확실·예산 초과·임베딩 오류는 로그에 남긴다. 정답·key_facts·근거 정답 인용문은 복원 판단에 쓰지 않는다.

## 실험 결과와 해석

- test 139문항에서 r30 정확도 75.54→89.99%, 입력 절감 50.65→47.87%. 차이 95% CI [+7.61,+21.28]%p, 완전정답 McNemar Holm p=0.004205.
- r50 정확도 92.51→94.54%, 절감 34.60→33.23%. 개선 CI가 0을 포함한다.
- 기존/repair의 temperature 요청이 달라 기법만의 인과 효과로 확정하지 않는다. test 결과를 본 뒤 설계한 사후 실험이다.
- 같은 repair 문맥 278개로 기본 추론을 재평가하면 procedure는 향상되지만 multi 일부가 부분 답변에서 NOT FOUND로 전환된다. r50의 채점 누락 2개는 0점으로 처리하지 않는다.
- 현재 r30은 거의 모든 문항에서 복원한다. 유사도 검사의 독립 기여, 동일 예산에서 우위, 일반화 성능은 아직 검증되지 않았다.
