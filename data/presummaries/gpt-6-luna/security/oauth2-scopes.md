- **OAuth2 Scopes:** Scopes are named permission strings without spaces, carried by a token; OAuth2 treats them as opaque strings. Examples: `users:read`, `users:write`, `instagram_basic`, `https://www.googleapis.com/auth/drive`. FastAPI integrates scopes with dependency injection and OpenAPI’s **Authorize** dialog and operation documentation. This page extends [OAuth2 with JWT](oauth2-jwt.md); full code: `docs_src/security/tutorial005_an_py310.py`.
- **1. Declare available scopes:** `OAuth2PasswordBearer(tokenUrl="token", scopes={"me": "Read information about the current user.", "items": "Read items."})`. The dict maps scope names to descriptions shown in docs.
- **2. Put granted scopes in the token:** `OAuth2PasswordRequestForm` reads space-separated `scope` into `form_data.scopes`. Store `" ".join(form_data.scopes)` in JWT `data={"sub": user.username, "scope": ...}`. The example grants whatever was requested; a real app must only grant scopes the user is allowed to have. Invalid username/password raises `HTTPException(status_code=400, detail="Incorrect username or password")`.
- **3. Require scopes with `Security()`:** `Security` accepts `scopes` and subclasses `Depends` in `fastapi.params`. Use `Security(get_current_user, scopes=["me"])` in `get_current_active_user`; it raises `400`, `"Inactive user"` for `current_user.disabled`. `/users/me/` requires `me` through that dependency; `/users/me/items/` adds `items`, accumulating as `["items", "me"]`; `/status/` uses `Depends(get_current_user)` and requires none.
- **4. Verify centrally with `SecurityScopes`:** Declare `security_scopes: SecurityScopes`; FastAPI fills it with scopes required by this dependency and all its dependants for the path operation. `security_scopes.scopes` is the required-scope list; `security_scopes.scope_str` is the space-separated string. The example’s `TokenData` has `username: str | None = None`, `scopes: list[str] = []`; it decodes JWT with `jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])`, reads `sub` and `scope`, and splits scope on `" "`. `ValidationError` and `InvalidTokenError`, missing username, or missing user raise `401`, `"Could not validate credentials"`. Missing required scope raises `401`, `"Not enough permissions"`. `WWW-Authenticate` is `Bearer` or, when scopes are required, `Bearer scope="me items"` per OAuth2. One function checks every endpoint. Dependency cache keys include effective scopes, so different scopes resolve separately in one request.
- **Trying it:** In `/docs` → **Authorize**, log in as `johndoe` / `secret` and tick scopes. Without `items`, `/users/me/items/` returns `401 Not enough permissions`; without `me`, `/users/me/` does too.
- **Choosing a flow:** Password flow is for your own frontend and API. For an authentication provider serving third-party apps, use another flow; authorization code is most secure (`OAuth2AuthorizationCodeBearer`). Scopes can also be set in decorators and routers with `dependencies=[Security(..., scopes=[...])]`.
