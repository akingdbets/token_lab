## GraphQL
- FastAPI is ASGI-based; ASGI-compatible GraphQL libraries can share an app with normal path operations: **Strawberry** (recommended; type-annotation-based, FastAPI integration docs), **Ariadne** (FastAPI integration docs), **Tartiflette** (Tartiflette ASGI), and **Graphene** (`starlette-graphene3`).
- Strawberry: `GraphQLRouter(schema)` is an `APIRouter`; add it with `include_router()` (it can use FastAPI dependencies for context). The example mounts it with `app.include_router(graphql_app, prefix="/graphql")`; endpoint: `/graphql`.
- Starlette’s old `GraphQLApp` (for Graphene) is deprecated; migrate to `starlette-graphene3` (almost identical interface) or consider Strawberry. GraphQL typically uses only `POST` for all operations; evaluate its trade-offs against a plain REST-style API.

## OpenTelemetry
- Telemetry comprises metrics (aggregated measurements), traces (per-request records of timed spans), and logs (timestamped events); OpenTelemetry is the standard for collecting/exporting them.
- FastAPI’s built-in support is enabled by default: HTTP request traces, metrics and logs; WebSocket traces and logs. `opentelemetry-api` is a core dependency; SDK and OTLP HTTP exporter come with `fastapi[standard]` or the `opentelemetry` extra. No instrumentation code is needed.
- Configure an HTTP/protobuf OTLP service with `OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_ENDPOINT`, and, if required, `OTEL_EXPORTER_OTLP_HEADERS`; exports go to `/v1/traces`, `/v1/metrics`, `/v1/logs`. A request to `/items/1` produces a `GET /items/{item_id}` span and request-count, response-duration, and active-request metrics. On FastAPI Cloud, metrics work automatically with `fastapi[standard]`.
- `FastAPI(telemetry={...})` accepts a `TelemetryConfig` dict from `fastapi.telemetry`. Defaults: `tracing=True` (HTTP/WebSocket spans), `metrics=True` (HTTP metrics), `logs=True` (validation failures/unhandled exceptions), `operation_spans=True` (dependency resolution, endpoint, response serialization, each `BackgroundTasks` task), `exclude=None` (function receiving ASGI `scope`; return `True` to skip request), `auto_configure=True` (add OTLP exporters for environment endpoints), and providers `tracer_provider`, `meter_provider`, `logger_provider=None` (use global providers). `operation_spans=False` leaves only the HTTP request span; metrics-only health-check exclusion can use `lambda scope: scope["path"] == "/health"`.
- If another library configured global providers before app startup, FastAPI uses them. With an environment OTLP endpoint it adds exporters to enabled providers; existing exporters continue. Set `auto_configure=False` to avoid duplicates if another library exports to that endpoint, or when setting providers up yourself (e.g. in lifespan). Provider creators manage shutdown; FastAPI manages components it adds.
- Background-task spans belong to the request trace but run after the HTTP response span ends and do not inflate response time. WebSockets get spans such as `WS /ws/{room}`; normal disconnect codes `1000`/`1001` produce no error logs.
- Unhandled exceptions are trace-linked logs (type, message, stack trace), even if the trace is unsampled; they may contain sensitive data—redact with log processors or set `logs=False`. Validation failures are warnings with route and error count, without invalid input. Providers are global by default; independent telemetry configuration for mounted sub-applications is not guaranteed.
- `fastapi.telemetry.get_telemetry_data(context=None)` returns `TelemetryData` for the current request/connection, or `None` after it finishes. Fields: `request`, `websocket`, `body` (read before validation), `values` (parsed arguments after dependency resolution), `errors` (validation errors with original input). Intended for synchronous OpenTelemetry span/log processors; read-only, apply your own redaction, and it is not automatically exported.
