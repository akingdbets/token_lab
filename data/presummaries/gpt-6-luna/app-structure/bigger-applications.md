- **Purpose and layout:** `APIRouter` groups path operations by module and works like a “mini `FastAPI`”, with the same decorators and parameters. The example package `app/` has `main.py`, shared `dependencies.py`, `routers/items.py`, `routers/users.py`, and `internal/admin.py`; each directory has `__init__.py`, enabling relative imports such as `from ..dependencies import get_token_header`.
- **Routes:** A plain router uses `router = APIRouter()` and declares operations with `@router.get(...)`, etc. Declare `/users/me` before `/users/{username}` so the fixed path wins.
- **Router settings:** `APIRouter(prefix="/items", tags=["items"], dependencies=[Depends(get_token_header)], responses={404: {"description": "Not found"}})` applies settings across its routes. Paths become `/items/` and `/items/{item_id}`. Routes get tag `items`; `update_item`, with `tags=["custom"]`, gets both tags. All document `404`; `update_item` also documents `403` (`"Operation forbidden"`). `read_item` raises `HTTPException(status_code=404, detail="Item not found")` if the ID is absent. Router dependencies run before decorator `dependencies=[...]`, then normal parameter dependencies; `get_token_header` runs for each request but its return value is not passed to the function.
- **Prefix rules and shared dependencies:** Prefix must start with `/` and must not end with `/`. If the include prefix and route path are both empty, `include_router` raises `FastAPIError("Prefix and path cannot be both empty ...")`. `get_token_header(x_token: Annotated[str, Header()])` raises `HTTPException(status_code=400, detail="X-Token header invalid")` unless `x_token == "fake-super-secret-token"`. `get_query_token(token: str)` raises status `400`, detail `"No Jessica token provided"`, unless `token == "jessica"`.
- **Main app and inclusion:** Import router modules (not their `router` variables) to avoid name collisions. `FastAPI(dependencies=[Depends(get_query_token)])` adds a global dependency to every operation, including router operations. `include_router()` accepts `prefix`, `tags`, `dependencies`, `responses`, `default_response_class`, `callbacks`, `deprecated`, `include_in_schema`, and `generate_unique_id_function`; these configure even routers you cannot edit. The example includes `users.router`, `items.router`, and `admin.router` with prefix `/admin`, tag `admin`, `get_token_header`, and response `418` (`"I'm a teapot"`). Operations can also be added directly to `app`.
- **Live inclusion and nesting:** Routers are not isolated sub-apps; operations share the app and OpenAPI schema. In this FastAPI version, `include_router()` appends an internal `_IncludedRouter` referencing the original router and include context; FastAPI combines prefixes and metadata when matching requests and generating OpenAPI. Later-added routes remain visible; routers can be nested before or after app inclusion. Don’t mutate `router.routes` directly after inclusion; use decorators and `include_router()`. A router cannot include itself or one that already includes it (assertion error). The same router can be included multiple times, e.g. with `/api/v1` and `/api/latest`; nested settings accumulate from outer include to inner router.
- **CLI:** Set `[tool.fastapi] entrypoint = "app.main:app"` in `pyproject.toml`; `fastapi dev`, `fastapi run`, the editor extension, and FastAPI Cloud then find the app without a path argument.
