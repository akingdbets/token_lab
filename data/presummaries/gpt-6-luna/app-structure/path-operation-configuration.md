- **General:** Every path-operation decorator (`@app.get()`, `@app.post()`, `@router.put()`, …) accepts configuration parameters for OpenAPI and the docs UI; they are decorator parameters, not function parameters.
- **Status code:** `status_code` accepts an `int`, a `fastapi.status` constant, or `http.HTTPStatus`; `IntEnum` values are normalized to `int`.
- **Tags:** `tags` groups operations in the docs UI. Use an `Enum` (e.g. `Tags.items = "items"`) for consistent names. Tags can also be set on an `APIRouter` or in `include_router()`; describe them with app-level `openapi_tags`.
- **Summary and description:** `summary` supplies the operation summary; if omitted, docs derive a title from the function name. `description` supplies its description; if omitted, FastAPI uses the function docstring, cleaned with `inspect.cleandoc` and supporting Markdown. Put `\f` in a docstring to keep internal notes such as Sphinx `:param:` lines out of OpenAPI: only text before the first `\f` is used (`route.description.split("\f")[0]` in `fastapi/routing.py`).
- **Response description:** `response_description` describes the main response and defaults to `"Successful Response"`.
- **Deprecation:** `deprecated=True` marks an operation deprecated in docs but does not stop it working. It can be set on a whole router; individual parameters can use `Query(deprecated=True)` etc.
- **Operation IDs:** Each operation gets a unique OpenAPI `operationId`. By default, `fastapi.utils.generate_unique_id` combines route name + path, replaces non-word characters with `_`, and appends the lowercased HTTP method (e.g. `read_items_items__get`). Set `operation_id` explicitly and keep it unique, or set `generate_unique_id_function` for the app, router, or include; it receives each `APIRoute`. An explicit `operation_id` overrides the function. If IDs use function names, every path-operation function must have a unique name, even across modules. Clean IDs matter most for generating client SDKs.
- **Excluding from OpenAPI:** `include_in_schema=False` keeps the endpoint working but excludes it from `/openapi.json` and docs; available on routers and in `include_router()`.
- **Additional responses:** `responses={...}` documents extra status codes and models.
- **`openapi_extra`:** A dict deep-merged into the generated OpenAPI Operation Object (`deep_dict_update(operation, route.openapi_extra)` in `fastapi/openapi/utils.py`). It supports OpenAPI `x-...` extensions and manually documenting request bodies. FastAPI does not read or validate a manually parsed body, though its schema appears in docs. It can document non-JSON content such as `application/x-yaml` while reusing a Pydantic model’s schema and validation; YAML errors and `ValidationError` can raise `HTTPException` with status `422`.
- **Other decorator parameters:** `response_model` and `response_model_*`, `response_class`, `dependencies`, `callbacks`, and `name`.
